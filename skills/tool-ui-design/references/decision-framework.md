# 工具 UI 通用決策框架

## 1. 蒐集證據

優先檢查可取得的需求、截圖、程式碼、控制項狀態、視窗尺寸與平台限制。區分：

- 已確認的實際行為
- 使用者明確偏好
- 尚未量測的推估
- 需要產品決策才能確定的事項

只有截圖時，不要假定看不見的流程；只有程式碼時，也不要假定實際排版與窄視窗表現正常。

## 2. 建立任務與狀態地圖

整理下列內容：

| 類別 | 要確認的問題 |
|---|---|
| 主要成果 | 使用者完成什麼才算成功？ |
| 操作頻率 | 哪些每次都用、哪些偶爾使用？ |
| 前置條件 | 操作前需要選取、載入或設定什麼？ |
| 系統狀態 | 哪些狀態必須持續看見？ |
| 編輯狀態 | 哪些變更尚未儲存、可以還原或會累積？ |
| 風險 | 哪些操作會寫檔、覆蓋、刪除或影響大量資料？ |
| 回饋 | 成功、失敗、處理中及部分完成如何呈現？ |

## 3. 決定資訊層級

將內容依任務價值分為主要操作、常用設定、即時狀態、次要設定、進階操作、危險操作與診斷細節。分類結果用來決定位置與顯著程度，不代表固定版面順序。

避免以下錯誤：

- 只因為資訊很多就全部收合。
- 只為了減少高度，把需要比較的數值擠成難以閱讀的一行。
- 把主要操作和不可逆操作做成同等醒目的相鄰按鈕。
- 重複顯示同一資訊，卻沒有增加確認、複製或防錯價值。

## 4. 選擇資訊呈現元件

依下列條件判斷，不使用固定數量門檻。先嘗試短標籤、同列排列與合併相關控制項，減少不必要的垂直空間；若目標面板寬度使內容難以辨識，再改用多列、分組或詳細視窗：

| 資訊特性 | 可考慮的呈現方式 |
|---|---|
| 少量、重要、短文字 | 緊湊摘要、同列欄位 |
| 可自然分群 | 多列分組、區段或卡片 |
| 數量多且需要橫向比較 | 表格、對齊欄位、排序或篩選 |
| 數量多但只需掌握重點 | 關鍵摘要加可展開詳細內容 |
| 即時快速更新 | 固定位置與寬度，避免版面跳動 |
| 偶爾除錯才需要 | 可收合診斷區或詳細視窗 |
| 長路徑或完整識別字 | 簡短顯示、可複製欄位或完整 Tooltip |
| 操作前必須確認 | 直接顯示，不得只放 Tooltip |

同一類資訊可能因面板寬度、更新方式或任務不同而採用不同元件。

## 5. 條件欄位與唯讀資訊

條件式欄位需回答：

1. 目前狀態下是否可操作？
2. 是否影響使用者接下來的決策？
3. 隱藏後是否仍看得出實際作用範圍？
4. 是否需要複製、比對或留下持續可見的確認？

唯讀資訊已在其他位置出現時，可以移除重複欄位；但若它提供完整內容、複製能力或防止操作錯誤，應保留或改用更合適的呈現方式。

## 6. 操作與風險

- 主要操作應容易找到，標籤使用使用者理解的結果或動作。
- 按鈕優先使用簡短且可辨識的文字；可用不會混淆的簡寫，並用 Tooltip 補充完整說明。多個短操作可併排，但需保留足夠的點擊區與區別。
- 次要與進階功能可以降低視覺權重，但不能因此失去可發現性。
- 高風險操作需與一般操作有足夠區隔，並在確認前顯示實際目標與影響。
- 確認視窗應說明即將發生的動作，而不是只詢問「是否確定」。
- 不可逆操作需說明復原方式；沒有復原方式時直接指出。

## 7. 狀態連續性

針對選取、切換 Mode、Scope、頁面、重新掃描與重新整理，逐一確認：

- 未儲存資料是否保留？
- 顯示狀態與實際作用目標是否一致？
- 背景更新是否造成重複運算、畫面跳動或效能干擾？
- 自動操作是否需要進度、錯誤或完成回饋？

如果產品需要在某次切換時清除狀態，應在操作前或結果區明確告知。

## 8. Tooltip 使用方式

Tooltip 適合補充：

- 短標籤、簡寫、代稱與路徑的完整內容
- 參數範圍與特殊計算方式
- 不常用的限制與技術細節
- 視覺、效能或資料影響

Tooltip 不適合承擔：

- 完成主要任務必讀的步驟
- 寫入或刪除的唯一警告
- 當前作用範圍的唯一提示
- 錯誤或執行結果的唯一回饋

## 9. 比較方案

只有方案有實質差異時才比較任務效率、可讀性與可發現性、空間效率、資料安全及維護成本。先說明差異與取捨；有實際量測時列出條件與結果，推估則標示「估算」。不要求固定權重或數字評分。

## 10. 實作與驗證

依變更風險選擇足以回答問題的檢查：文案與 Tooltip 小改可用靜態檢查；排版變更檢查受影響的尺寸與狀態；互動、未儲存資料與寫入操作則驗證相關 runtime 行為。只有較低成本的證據不足時，才啟動或控制實際應用程式。回報已驗證與未驗證項目，不把 Build 成功當成畫面或互動已驗證。
