# 工具 UI 設計與檢查

## 目標

本 skill 只用於工具 UI 的規劃、製作、檢查與優化，不延伸到其他介面或開發工作。依任務、資訊、狀態與平台限制設計；工具面板預設簡潔、省空間，但不套用固定行數或版型。

## 適用邊界

- 使用者藉介面建立、編輯、設定、管理或除錯其他內容或系統時，才視為工具 UI。
- 平台名稱或控制項外觀不能單獨決定是否套用；Omniverse、Kit、Composer 上的產品介面仍不適用。

## 開始前

1. 辨識使用者要討論、規劃、檢查或實作；只要求討論或檢查時不修改檔案。
2. 有現有介面、程式碼或截圖時，先檢查實際行為與限制，不只依控制項名稱推測。
3. 需要詳細判斷時閱讀 [通用決策框架](references/decision-framework.md)；製作 Kit／Composer 工具面板時再閱讀 [Omniverse Kit UI 規則](references/omniverse-kit-ui.md)。

## 工作流程

### 建立任務模型

確認主要使用者與主要成果，並區分：

- 常用操作與次要操作
- 必須持續可見的狀態與按需查看的細節
- 可編輯輸入、唯讀資訊與系統自動產生的值
- 暫存、預覽、已儲存與可還原狀態
- 寫入、覆蓋、刪除或其他高風險操作

缺少會改變設計方向的產品意圖時才詢問使用者。可以從程式、截圖或平台規則確認的事實，先自行檢查。

### 選擇呈現方式

依資訊的重要性、數量、文字長度、更新頻率、比較需求及可用空間，選擇單列、多列、表格、分組、收合區、詳細視窗或 Tooltip。預設先移除無助於任務的重複資訊與冗長文案，將相關控制項及短資訊併排；寬度不足或需要清楚比較時再分行。

- 按鈕與欄位標籤優先使用容易辨識的短文字；語意清楚時可簡寫，並以 Tooltip 補充完整名稱、用途與細節。簡寫不得讓使用者猜測操作結果。
- 關鍵資訊與重大風險不得只藏在 Tooltip。
- 唯讀欄位是否保留，取決於使用者是否需要確認、複製或避免選錯範圍。
- 條件式欄位只在對目前 Mode、Scope 或工作狀態有意義時顯示，但隱藏後仍須讓使用者知道實際作用範圍。
- 主要操作依任務順序與使用頻率安排；進階與高風險操作不得搶走主要流程的視覺優先權。

### 保護狀態與資料

- 切換選取、Mode、Scope、頁面或分頁，不得意外清除未儲存工作，除非產品流程明確要求。
- 寫入、覆蓋與刪除操作應依風險顯示實際目標、影響範圍、可否還原及必要確認。
- 不因 UI 整理而改變既有資料語意、預設值或持久化行為，除非使用者明確要求。

### 提案、實作與驗證

- 討論或檢查時說明具體問題、設計理由與取捨；多個方案有實質差異時才比較，不強制評分。
- 實作時只改授權範圍，保留未要求改變的行為；依風險選擇最低充分驗證，並區分已驗證與未驗證項目。
- 排版變矮仍需確認可讀性、可發現性與操作風險。提供量測數字時說明條件，推估則標示「估算」。
