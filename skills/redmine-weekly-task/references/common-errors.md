# Common Errors

## 1. 查不到資料

先檢查以下幾項：

1. 起訖日期是否正確。
2. 是否真的有 issue 指派給目前帳號。
3. issue 到期日是否落在指定日期範圍。
4. 是否有專案瀏覽權限。

## 2. API 回傳 401 或 403

通常代表以下其中一種情況：

1. API key 錯誤。
2. API key 已失效。
3. 帳號沒有對應專案權限。

## 3. 同事照做但結果和你不同

常見原因：

1. 使用的起訖日期不同。
2. 人工修正清單不同。
3. 查到的是 `me`，所以每個人看到的是自己的 issue。

## 4. 專案代碼抓不到

表示該 Redmine project description 內可能沒有明確的 `專案代碼` 或 `專案代號` 文字。

處理方式：

1. 人工補值。
2. 在專案概觀補上標準格式後再重跑。

## 5. O/M/P 解析失敗

表示 issue 描述內可能沒有固定格式。

建議格式：

1. `難度：S`
2. `三點估算：O/M/P = 1h / 2h / 3h`

若格式不一致，請用人工修正清單補值。

## 6. PERT 看起來和 Redmine issue 內文字不同

這個 skill 的規則是：

1. 以 O/M/P 重新計算 PERT
2. 不直接信任 issue 文字中的 PERT
3. 最後四捨五入到 `0.5h`

## 7. 最容易漏掉的 input

最常漏的是：

1. 週次
2. 輸出檔名
3. 人工修正清單
4. Redmine base URL

## 8. 產出檔被寫進 skill 資料夾

這是不正確的輸出位置。

處理方式：

1. 實際產出檔一律寫到 skill 資料夾外。
2. 若使用者只提供檔名，預設寫到工作區根目錄。
3. `assets/` 內的 markdown 只能當模板或範例，不可覆寫。
